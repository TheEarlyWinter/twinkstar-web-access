# 从 1.1.1 迁移到 Hanako V2

## 安装边界

本适配以原版 1.1.1 为基线。V2 使用 `manifestVersion: 2` 的 App 装载机制，而不是给旧 `trust: full-access` 清单改一个版本号。

通过 Hana 的正式扩展管理入口导入安装 ZIP，并由用户审阅所申请的能力。不要手工修改 Hana 的应用权限账本或运行时配置。

1. 先在扩展管理中停用旧版 Twinkstar 插件，避免同名工具重复注册，以及旧代理占用默认的 `3457` 端口。
2. 导入 V2 安装包并审阅权限。如果安装器报告同 ID 来源冲突，按正式管理界面提示处理；不要手工挪动托管目录。
3. 在 App 设置中重新确认浏览器类型、用户数据目录与代理端口。默认不允许操作非本 App 创建的标签页。
4. 在用户自己管理的浏览器中开启远程调试。App 不替用户复制 Profile、重启或关闭浏览器。
5. 确认 App 已启用，并为实际使用的 Agent 启用其工具；从 `twinkstar-web-access_browser_status` 开始检查。

迁移时不自动安装或启用 App，不关闭原浏览器，不把旧标签页视为新 App 的自有标签页。

## 数据与配置

旧版数据位于 `plugin-data/twinkstar-web-access`，V2 App 数据位于独立的 `app-data/twinkstar-web-access`。不直接扫描或复用旧版的代理令牌、标签页所有权登记和浏览器 Profile。

原设置需要在 V2 设置页面确认。旧数据不会因交付安装包被删除。若需保留站点元信息，应通过用户明确授权的正式文件/资源入口处理，不把整个旧数据目录复制进 App 包。

V2 不使用脱离宿主的后台进程。代理由宿主受管运行时启动和停止；停用、卸载及相关权限撤销由宿主回收运行时进程树。代理停止不意味着关闭用户浏览器，也不承诺清除已经交给模型的网页内容。

## 权限解释

- `app/tools.expose-to-model`：允许 Agent 使用 App 注册的浏览器工具。
- `app/runtime.execute`、`app/runtime.native`、`app/runtime.network`：运行受管 Node 代理，访问本机 CDP 和必要的浏览器发现文件。
- `app/resources.read`：为上传等功能检查并读取用户明确授权的文件；Windows 原生运行时的额外读根也需要相应授权。
- `app/session.stage-file`：将截图登记为当前调用会话的产物。

原生受管模式不等于完全秘密隔离：Linux/macOS 原生程序可读取当前 OS 用户可读的文件。代码仍应只读取必要的浏览器发现文件，并仅在 App 数据目录写入自己的业务数据。不要因此授予操作其他标签页、上传任意文件或浏览器内部 URL 的权限。

本版本不申请 `app/runtime.local-machine`，也不在原生运行时失败后静默切换到更宽泛的本机模式。

## 跨平台约束

Linux/macOS 的用户浏览器发现路径必须在 App 主入口解析并传递给受管程序；受管程序的 `HOME` 可能被重定向，不能据此猜测用户 Profile。

Windows 原生受管程序使用独立运行时身份。它需要当前宿主提供可用的 native helper/身份初始化，以及浏览器目录的明确读取授权；这些是宿主和系统条件，不能由 App 的 ZIP 绕过。条件不满足应报告实际错误。

## 验证边界

单元测试与 CDP 协议夹具只使用合成网页信息、临时文件与本地服务，不读取真实 Cookie、登录页、Profile 内容或用户文档。通过它们不等于已经在 Windows/macOS 的真实浏览器中完成验证。

官方静态校验确认包结构与清单；隔离 AppHost 启动验证确认 V2 装载。若通用启动检查不授予原生运行权限，代理的真实受管启动必须单独验证，不能用启动检查通过代替。
